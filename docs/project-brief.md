# Stable or Gone Project Brief

## Summary

Stable or Gone (SOG) is a source-backed stablecoin registry.

It records stablecoin entities, issuers, depeg events, reserve disclosure, redemption access, lifecycle changes, evidence, and known unknowns.

SOG is not a market dashboard, a rating site, or an investment recommendation product.

## Core positioning

```txt
Stable or Gone = a stablecoin history and evidence registry.
```

The project focuses on:

- stablecoin status
- issuer identity
- peg asset
- collateral / reserve model
- depeg and recovery history
- failed / discontinued / migrated tokens
- reserve disclosure and attestation history
- redemption and mint/burn access
- lifecycle changes
- source-backed evidence
- unclear or unresolved fields

## What makes SOG different

SOG does not try to beat market-data platforms on live supply, price, volume, or chain-level dashboard views.

SOG instead focuses on:

- historical dossier pages
- event timelines
- issuer context
- reserve and redemption history
- source coverage
- evidence quality
- lifecycle mapping
- known unknowns

## v0 principle

v0 should be useful as a static registry with a small but carefully structured seed dataset.

The first version should prioritize:

- clear data model
- safe methodology
- useful detail pages
- report/correction flow
- terminal-style registry UI
- support/donation route

## Do not build in v0

- realtime price monitoring
- live depeg alerts
- user accounts
- user voting
- database
- paid API dependency
- safety score
- yield comparison
- automatic canonical updates

## Default language

English is the public default language for v0.

Japanese support can be considered later through localized UI/page copy, but canonical data should remain stable and language-neutral where possible.
