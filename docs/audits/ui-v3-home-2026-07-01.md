# UI v3 Editorial Ledger Home audit

Status: supporting audit  
Date: 2026-07-01  
Roadmap item: PR #263

## Purpose

Replace the Home-specific Modern Data Product/SaaS composition with the approved Editorial Ledger registry front page while preserving canonical data, routes, search, guide publication metadata, and structured data.

## Removed composition

```text
PageHero marketing block
coin-stack decoration
blue grid and glow
four MetricCard KPI blocks
four generic registry entry cards
three gradient guide cards
hard-coded selected-slug showcase
large SupportBanner CTA
```

The removed selected-record section was not canonical priority data; it was a fixed UI-v2 showcase. All records remain available through the register and search.

## New hierarchy

```text
Editorial masthead and review-through date
One-line canonical registry totals
Cross-registry search
Latest material changes
Current lifecycle counts
Recently reviewed stablecoin records
Metadata-driven guides
Methodology, Glossary, Models, Updates, and Corrections entrypoints
```

## Deterministic rules

```text
Featured guides:
getFeaturedGuides(4)
Published + featured metadata, existing catalog order by published date

Latest material changes:
Canonical events with event_date
Descending event_date, then descending event ID
First five

Recently reviewed stablecoin records:
Descending last_verified_at, then stablecoin name
First eight

Registry review-through date:
Latest non-null date across stablecoin last_verified_at,
event event_date, and featured-guide publication/current dates
```

## Data preservation

```text
Canonical stable assets: 98
Canonical record changes: 0

Guide metadata changes: 0
Search record types preserved: Stablecoin, Organization, Event
Logo changes: 0
```

## Truth and interpretation

The Home lifecycle summary includes this explicit boundary:

> Lifecycle describes the recorded state of an asset. It is not a safety score, recommendation, or market assessment.

The page does not introduce price, supply, market-cap, holder, score, verification-badge, or unsupported legal data.

## Responsive behavior

- masthead columns collapse deliberately;
- registry totals move from four columns to two and then one;
- material-change records move from metadata/content columns to one column;
- guide columns become one column;
- search retains labels, result announcements, Escape close, and direct-term controls;
- recent-record table remains a deliberate horizontal comparison surface until the final compact-layout work in PR #269.
